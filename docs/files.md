# 文件操作

设置 `GATEWAY_FILES_ENABLED=true` 后重启，文件工具只对已配置的 Telegram 管理员私聊开放。可访问服务进程有权限访问的本地路径；不执行 shell。默认关闭。

| 工具 | 功能 |
| --- | --- |
| `gateway_file_list` | 目录分页，每页最多 100 项 |
| `gateway_file_info` | 类型、大小、修改时间 |
| `gateway_file_read` | UTF-8 文本预览，每次最多 12000 字符 |
| `telegram_send_document` | 生成并发送、仅保存、发送已有文件 |
| `gateway_file_propose` | 准备文件替换或删除，返回路径、摘要与确认指令 |
| `gateway_file_apply` | 用户在新消息中完整回复确认指令后执行 |

生成目录默认为 `<GATEWAY_DATA_DIR>/files/generated/`；可用 `GATEWAY_GENERATED_FILES_DIR` 更改。生成 Markdown、TXT、CSV、JSON、HTML 和代码等 UTF-8 文件后返回实际保存路径。`generate` 遇到同名文件时另存子目录，保留上传文件名；`save` 可以指定完整目标路径，但目标存在时拒绝覆盖，父目录必须已经存在。复杂二进制文档可以通过 `existing` 发送，未提供 PDF 或办公文档渲染器。

读取、发送和替换最多处理 20 MiB 的普通文件；文本预览拒绝非 UTF-8 内容，文件读取和修改拒绝最终路径为符号链接的目标。使用者应按操作系统权限决定服务可访问的范围。生成文件默认权限为 600，目录为 700；不要把用户数据目录提交到源码仓库。

修改或删除前，先展示具体操作及路径。确认指令为 `确认文件操作 <确认码>`，有效期 15 分钟，必须由管理员在新的消息中完整发送。执行前再次核对文件内容及元数据；文件变化后需重新准备。重启会清除尚未执行的提案。替换通过同目录临时文件及重命名完成，删除仅针对一个文件，不支持递归删除目录。

文件交付尝试在网络请求前写入现有 SQLite。同一消息操作重复调用或重启后不会重复发送；如果网络返回结果不明确，会提示核对聊天中的文件，不能宣称发送成功。需要再次发送时，由用户发起新的请求。交付收据只保存请求摘要及结果元数据，不保存文件正文。生成文件作为独立文件保留，备份时也应包含生成目录。
