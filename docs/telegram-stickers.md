# Telegram 贴纸与表情素材

管理员私聊默认支持素材收录和模型选择，无需新增开关。素材仅在同一机器人和管理员会话内使用，不包含预装素材包。

## 接收与识别

- 新收到的 JPG、PNG、WEBP 图片或图片文件可以收录为表情素材。引用的其他发送者图片不会作为管理员新素材收录。旧普通图片不能自动补齐元数据，可重新发送收录。
- 静态图片交给支持视觉的模型。通用 API 需使用支持图片的模型并设置 `GATEWAY_API_VISION=true`。
- GIF、MP4 和 WEBM 可通过 FFmpeg 提取最多四个画面作为预览；失败时使用可用缩略图，否则仅保留素材信息。TGS 使用静态缩略图。有限采样不代表理解完整动作。
- 以文件形式发送的图片、引用和历史图片仍作为图片输入。旧 SIWC 检查点中的图片文件包装在请求副本中修正，不修改历史或原始检查点；PDF 等普通文件保持文件输入。

## 选择与发送

`gateway_sticker` 使用 `list` 查找最多 8 个不同素材，再用稳定 `key` 执行 `select`。支持单个 `query` 或最多三个 `queries`，多词命中优先。后续轮次可复用已知 key，仍核验机器人、会话及本地记录；较早素材可通过 `history_index` 检索。每轮最多一个素材，选择回执包含 `source_format`。

- 普通图片和静态贴纸在发送前转为 WEBP，最长边 512 像素、最大 512 KiB，保留原背景。
- 最多 3 秒的动图或视频优先转为无音轨的 VP9 WEBM 视频贴纸，最长边 512 像素、30 FPS、最大 256 KiB。
- 不符合视频贴纸条件时发送普通动图，保留完整时长。原生 GIF 可复用 ID，文件素材转换为 H.264 MP4 后重新上传。
- 静态、视频素材重新下载处理并上传，避免旧分类记录绕过转换；TGS 继续使用原生贴纸 ID。

所有转换均发生在发送前。`select` 只登记意图，收到有效回执才确认送达。发送失败或结果不明后不切换接口、不自动重发。使用现有持久投递流程，无新增数据库表。`gateway_sticker_note` 可添加最多 280 字、基于观察或用户说明的素材备注。

## 本机依赖与限制

运行 Sophon 的环境需安装 `ffmpeg` 和 `ffprobe` 并加入 PATH，FFmpeg 需支持 libwebp、libvpx-vp9、libx264。Windows 安装后需重启 Sophon 所在进程以刷新 PATH。缺失时会报告依赖错误；更新代码本身不会安装这些程序。转换仅在本机运行，不调用付费转换服务。

源文件最多 20 MiB，文件动图最多 120 秒，每次转换子进程最多 30 秒；临时文件结束后清理。重新转换会增加发送延迟。图片和视频转换可用性取决于本机 FFmpeg 编码器。

此工具用于正式 Telegram 对话，微信不提供该工具。独立的主动消息 `GATEWAY_TELEGRAM_STICKER_IDS` 白名单发送路径不变。

测试使用生成的纯色图片、视频和合成标识，不使用真实聊天、个人素材或私人测试夹具。
