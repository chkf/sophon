# Telegram 贴纸

管理员私聊支持接收、查看和发送贴纸，无需另外启用开关。更新并重启服务后，给机器人发送一张贴纸，再发送“请发回刚才的贴纸”即可使用。

## 输入与识别

- 静态 WEBP 贴纸作为图片输入，识别效果取决于当前模型及 Provider 的图片能力。通用 API 需配置支持图片的模型，并设置 `GATEWAY_API_VISION=true`。
- 动画 TGS 和视频 WEBM 贴纸使用 Telegram 提供的静态缩略图。模型只能看到预览，不能据此判断完整动作。
- 没有缩略图、文件超限或下载失败时，保留贴纸元数据并明确标注画面不可读；仍可选择原贴纸发送。

## 选择与发送

模型使用 `gateway_sticker`：先 `list` 查找，再用返回的 `key` 执行 `select`。默认查询当前消息与最近 50 条历史；较早记录可通过历史检索确定索引，再指定 `history_index`。

每轮最多选择一个贴纸，仅限同一机器人、同一管理员私聊实际收到并保存的记录。工具不接受任意 `file_id`，不会下载整个贴纸集或生成新贴纸。贴纸可以单独发送，也可与文字一起发送；发送使用原始 Telegram `file_id`，保留动画或视频格式。

`select` 只登记意图。实际发送复用持久化投递流程，收到有效 `message_id` 后才记为送达；结果未知时不自动重发。元数据随现有聊天历史保存，不新增数据库表。旧历史中未保存贴纸信息的记录无法自动补齐，可重新发送贴纸。

此功能支持通用 API、OpenRouter 和 SIWC 的正式 Telegram 对话。微信不提供该工具。已有主动消息使用的 `GATEWAY_TELEGRAM_STICKER_IDS` 白名单保持独立；本次不扩展自定义 emoji、GIF 消息或动画逐帧理解。

测试使用合成文档图标、占位文件标识和模拟传输，不包含真实贴纸文件、账号信息或聊天记录。
