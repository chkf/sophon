# Sophon 控制中心

控制中心用于浏览数据和观察真实执行过程，包含五个页面：聊天历史、Core / Recent、上下文、主动任务和主机监控。聊天模型、语音、生图、主动渠道切换、诊断和日志继续使用已有 slash 面板；网页不提供这些操作的第二套入口。

## 启用和登录

默认关闭。设置 `GATEWAY_CONTROL_PUBLIC_URL` 后，控制中心复用 Gateway 的 HTTP 服务和现有主 SQLite，不新增数据库或生产依赖。先按 README 初始化数据目录；控制中心不会创建默认 Core 或自动迁移旧数据库。

本机使用，或通过 SSH 转发到本机：

```dotenv
GATEWAY_HOST=127.0.0.1
GATEWAY_PORT=8790
GATEWAY_CONTROL_PUBLIC_URL=http://127.0.0.1:8790/control/
```

远程 HTTPS 使用自己的域名：

```dotenv
GATEWAY_HOST=127.0.0.1
GATEWAY_PORT=8790
GATEWAY_CONTROL_PUBLIC_URL=https://gateway.example.com/control/
```

反向代理只转发 `/control/`（以及 `/control` 跳转），保留原始 Host 和 Origin。不要把 `/healthz` 或 `/__gateway/takeover` 暴露到公网。配置必须以 `/control/` 结尾；公网地址只支持 HTTPS，HTTP 仅支持显式 localhost / 127.0.0.1 / [::1]。启用时 Gateway 必须绑定回环地址。

构建、按既有方式重启后，在管理员 Telegram 私聊发送 `/status`，打开返回的网址并粘贴一次性登录码。登录码 5 分钟有效、只可使用一次；再次请求会撤销前一个未使用的码。入口命令不会调用模型或写入聊天历史。

登录会话 8 小时有效，保存在 HttpOnly / SameSite=Strict Cookie 中；HTTPS 使用 Secure 的 `__Host-` Cookie。登录码和会话只在进程内保存，重启后失效。所有数据接口检查精确 Origin 和 CSRF，不允许跨域访问。关闭方式是移除 `GATEWAY_CONTROL_PUBLIC_URL` 并重启。

## 页面行为

### 聊天历史

按会话、日期和关键字分页浏览 SQLite 原文，搜索结果可以打开前后文。仅提供读取，不修改或删除原始聊天。日期按 `GATEWAY_TIMEZONE` 解释。Telegram 与微信使用实际会话映射，不预设渠道分工。

附件从所选消息的已保存引用读取，只能访问数据目录内的媒体文件；不存在、越界、符号链接和超过 32 MiB 的附件会明确拒绝。没有任意目录浏览或路径下载接口。

### Core / Recent

读取实际生效的 Core 和 Recent，支持修改前后对照。写操作复用已有内容校验、修订号检查和本地工具；保存时在正式消息队列的安全边界执行。旧页面不能覆盖更新的修订，冲突时需重新加载。

Recent 可以修改、归档、恢复和删除；删除保留已有防复活凭据。操作 Recent 不删除原始聊天，也不意味着从历史压缩检查点中抹去相同信息。心理和动作描写开关使用 `/expression`。

### 上下文

显示 Core / Recent 的本地注入内容、修订和可读取的检查点元数据。SIWC 的不透明压缩正文不作解码或推测。没有可用记录时显示缺失或不支持，不把本地文本长度换算成精确上下文 token。最近请求用量和上下文状态的口径以页面标注为准。

### 主动任务和调用轨迹

目前记录 Heartbeat 的计划生成、主动判断、条件跳过和交付过程。每次执行有独立 ID、开始/结束时间、状态和有序步骤；模型和工具步骤可展开查看实际输入、参数、返回结果及已回报用量。

- 模型静默、冷却/免打扰等条件跳过、调用失败、确认送达、交付结果未知分别呈现。模型只返回 `SILENT` 时不补写原因。
- 模型步骤来自 Provider 实际请求；工具步骤来自真实执行。文字中声称“已经调用”不会生成工具成功记录，也不展示模型的隐藏思考过程。
- 发送前记下的是**发送尝试**。只有渠道确认后才显示送达；不确定结果保持未知，不为补齐轨迹重放消息。
- 每次模型调用的输入、缓存输入、输出等用量只采用上游实际回执。缺失字段不填零，部分步骤缺少回执时不把已回报数值称为完整任务总量。
- 正常业务运行不依赖观测写入成功；观测失败不会触发额外调用或改变重试、额度及防重发策略。

开启后才开始采集，既有历史不会伪造为完整轨迹。轨迹存入现有 SQLite 的 `gateway_state` 诊断分区，默认最多 200 次、保留 7 天；达到数量或时间上限后清理旧记录。每次最多 80 个步骤、整条 128 KiB，单步输入/输出有限额，截断会标注。反复出现的相同跳过状态会合并采样，避免每分钟写一条相同记录。

记录在写入前移除配置凭据、认证字段和二进制/不透明推理内容。任务输入和输出仍可能含有用户自己的文字，因此轨迹与聊天历史一样属于本地私有数据，随原有数据目录备份；不要提交到源码仓库。关闭控制中心会停止新轨迹采集，已有记录不自动删除。

### 主机监控

每 5 秒采样，最多保留 120 个点。CPU 和网络首次采样显示等待；Linux 内存使用 MemAvailable，磁盘仅代表数据目录所在文件系统。网络是可见非 loopback 接口计数，包含虚拟接口时可能重复统计，不能当作云服务账单流量。不调用 shell 或额外系统服务。

## 验证

```sh
npm run typecheck
npm test
npm run build
```

可选浏览器验收：

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
npm run test:control-ui
```

也可以用 `SOPHON_UI_BROWSER_PATH` 指定已安装的 Chromium 可执行文件。脚本 `scripts/control-ui-smoke.mjs` 使用合成数据，不连接真实聊天服务，不消耗模型额度。生产启用后还需在自己的浏览器验证域名、登录和反向代理；提交代码不会部署服务器。

## 登录链接与历史管理

`/status` 返回含五分钟一次性凭据的链接及备用登录码。凭据放在 URL fragment 中，浏览器先从地址栏清除再登录；手动输入仍可用。不要转发登录链接。部署的 HTTP/HTTPS 和访问范围要求不变。

聊天历史按最新消息在前显示，原始消息索引仍用于定位。删除需要明确确认和当前消息版本，未结算交付会阻止删除；删除后保留筛选、分页和滚动位置。删除会更新历史索引、Recent 进度和上下文覆盖游标，并在自然重连时重建可见历史。已经进入活动连接、不可读压缩检查点或备份的内容不会因此被追溯抹除。

记忆图页提供主题、节点、原文来源和回填状态的只读浏览。迁移、回填及分类模型设置分别通过 CLI 和 `/model` 完成。
