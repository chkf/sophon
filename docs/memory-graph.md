# 记忆图

记忆图从正式、完整送达的聊天建立检索线索，保留原始消息来源。主题分层、衰减权重、检索、后台整理及来源验证在本地 SQLite 中运行。模型分类和整理使用独立 SIWC 会话；主聊天使用通用 API 或 OpenRouter 时仍需要另行配置 SIWC，不会自动转用付费接口。当前不提供通用 API 记忆分类适配器。

统一自动启用，旧配置的 `GATEWAY_MEMORY_GRAPH_ENABLED=false` 不再生效。准备扩展和入队不会调用模型；后台回填、分类和整理会消耗所配置 SIWC 模型的套餐额度。分类模型默认 `gpt-6-luna`，实际必须出现在当前账号模型列表中，可通过 `/model` 的“记忆分类模型（SIWC）”选择，或 `/model memory <model-id>` 设置。整理使用当前 SIWC 聊天模型。模型不可用时任务等待重试，不悄悄替换模型。

## 自动准备

首次正常启动时，在取得 Gateway 实例锁后，先验证本地数据库并保存完整 SQLite 快照，再安装记忆图扩展、登记历史回填和 Recent 引用。无需手动运行迁移或 bootstrap 命令；没有历史的新安装也可直接准备。模型分类在服务启动后由后台逐轮执行，正常聊天优先。

自动准备只针对已有、已初始化的 schema v2 数据库中的记忆扩展，不创建替代 Core，不改写原始聊天，不升级不兼容的主 schema。快照保存在数据目录的 `.memory-migration/`，预检要求至少三倍数据库大小的可用空间。已有扩展和回填登记会复用；重启不会重复创建任务、快照或重置失败任务。停用期间新增的未入图历史会在再次启用时补齐。

空间或快照失败时，保持正常聊天并在控制中心显示准备失败；解决后重启重试。数据库损坏仍拒绝启动。首次回填可能较久，模型或额度不可用时显示等待状态，不切换到付费接口。可在控制中心记忆图页查看进度，入队不代表建图已经完成。

新 clone 和升级安装使用相同的启用策略，无需修改旧 `.env`。更新器的下载、构建、测试和只读兼容检查不会操作生产记忆图；自动准备仅在实际启动业务进程时执行。

## 手动维护（可选）

诊断、显式重建或恢复时仍可使用以下命令。先停止服务；`./data` 替换为数据目录，`70001` 为合成管理员示例。手动回填需要已有正式管理员会话。

```sh
npm run memory -- inspect ./data
npm run memory -- migrate ./data --stopped
npm run memory -- bootstrap ./data --owner 70001 --stopped
npm run memory -- status ./data --owner 70001
```

## Recent 和来源

自动准备和手动 `bootstrap` 都会登记 Recent 引用；已有正文仍由 Recent 表保存，记忆图不复制正文。修改、归档、删除会同步引用状态，未完成事项保留。集成后停用重复的普通 Recent 后台整理；聊天中的 Recent 工具仍可用。也可单独执行：

```sh
npm run memory -- recent-migrate ./data --owner 70001 --stopped
```

分类只以完整对话原文为证据，不把助手建议当成用户决定。长对话分批处理，并检查来源指纹及任务租约。原文被修改或删除后，受影响节点失效，不继续显示旧摘要。检索不会自动提高记忆权重；强化需要额外证据。

## 上下文窗口

只有历史回填完成且没有缺失、过期或失败分类任务时，SIWC 才能在安全边界采用 Core、独立描写设置、有限记忆视图及最近三个本地日历日期的完整对话。日期按 `GATEWAY_TIMEZONE` 配置计算，包括今天和前两天；不是滚动 72 小时。跨日问答完整保留，未答消息和无法确定日期的消息不因窗口而丢弃。

存在未结算交付或未解决工具结果时不切换上下文。准备失败、窗口超过安全预算或记忆图尚未就绪时保留原链，不静默缩短窗口。图启用时不回退旧的周期性聊天压缩。通用 API/OpenRouter 的聊天历史策略不使用此 SIWC 窗口，但可以使用已接入的记忆检索工具。

没有启用记忆图时，SIWC 使用独立的纯聊天维护流程：在每日首次 Heartbeat 计划前检查七天期限，或达到容量阈值时处理；仅通过已认证 WebSocket 的 `context_management` 获取实际压缩检查点，不调用独立 compact HTTP 接口。工具结果和 Core 不作为聊天压缩材料。失败保留原状态。

## 关闭、恢复与验证范围

停止服务会停止后台任务；扩展表仍保留，不会自动删库。旧版本可能拒绝该扩展，不应直接用旧程序打开；需要回退时停止服务并恢复迁移前的完整快照。已有快照无法包含之后新增的数据，请先保留现状备份。

整理操作可通过停机命令 `npm run memory -- undo ./data --owner 70001 --operation <operation-id> --stopped` 撤销，受版本校验约束。CLI 不提供绕过校验的强制覆盖。

自动测试使用新建的合成数据库、合成消息和模型响应，不读取生产凭据或真实聊天；真实模型分类质量和部署资源消耗需在启用后观察。

## 回忆顺序与表达

一般回忆先参考本轮相关线索；寻找其他记忆时使用 `gateway_memory_search`，已有 ID 时直接用 `gateway_memory_read` 展开。内容足以回答时不重复查原文；核对原话、准确时间、矛盾或缺漏时仍可主动调用 `gateway_read_history`。未启用记忆图时按需检索历史。

回复自然谈论内容，不主动播报检索过程；询问出处时如实说明。记不清时说明不确定，不编造，也不把已知内容说成忘了。通常不复述精确日期时分，但日程、时间核对等任务仍保留必要精度。原始时间、来源、检索算法和数据库结构不变。

## 分层分类与无信息交流

分类先提供全部顶层主题，模型选择一到两个大类，也可建议新增顶层主题；随后只展开选中分支，选择更具体的主题。分支过大时逐层展示完整的直接子目录，不按关键词或热度偷偷截掉已有类别。根选择与下降进度保存在现有任务记录中，重启可以继续；目录名称、别名或结构变化时重新选择。输入超过安全上限会明确退避，连续失败后保留失败状态，不以不完整目录继续分类。

新主题在最终分类通过校验后才写入。第二阶段跳过或失败不会留下空提案；既有名称和别名会先用于去重，跨出所选分支或未经展开的新增路径会被拒绝。此过程通常需要两次分类调用，大分支可能更多，使用既有模型额度与退避策略。

分类提示要求跳过只有“没听清、请再说一遍”等澄清、没有新增信息的重复应答和无后续价值的一次性问答；不把转写错误或模型猜测当作事实。同一轮有明确纠正、计划或偏好时仍保留有依据的部分，不使用关键词硬过滤。原始聊天仍保存，更新不会删除或重新分类既有记忆。测试验证协议、路由和提交边界，真实模型的语义判断质量仍需实际观察。
